# Apple 风格老人模式 UI 重设计

## 状态

- 日期：2026-07-29
- 用户批准：已批准。用户在现有 UI 审计后要求“按照你的建议，执行”。
- 实施范围：前端视觉系统与核心老人流程的信息层级。

## 真实目标

降低当前界面的视觉噪音和模板化、AI 生成感，同时保留已经验证过的老人友好特征：日文直白文案、大触控目标、单任务流程、语音与按钮双路径、明确的演示数据边界。

## 设计原则

1. 内容优先于装饰。
2. 每页只保留一个高强调主操作。
3. 使用字体、间距和分隔线建立层级，减少独立卡片和粗边框。
4. 老人主操作保持 56–64px，高频或辅助操作不低于 44px。
5. 状态不能只依赖颜色；继续同时提供文字、图标或结构提示。
6. 不引入渐变、玻璃拟态、装饰光效、悬浮气泡或多余动画。

## 方案比较

### A. 仅 CSS 换肤

只调整颜色、字体、圆角和阴影。

- 优点：代码改动最小。
- 缺点：无法解决首页入口同级、结果页重复大按钮、演练页卡片套卡片等结构问题。

### B. 组件结构与视觉系统同步调整

保留路由、状态与业务逻辑，修改页面语义分组和样式。

- 优点：能真正消除模板感，又不扩大到后端或数据模型。
- 缺点：需要更新前端流程测试和多个页面组件。
- 结论：采用此方案。

### C. 全面重做导航和信息架构

重新设计路由、底部导航和家属模式。

- 优点：自由度最高。
- 缺点：超出本次“美化当前 UI”的范围，增加行为回归风险。

## 视觉系统

### 字体

- 字体栈：`-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Noto Sans JP", sans-serif`
- 正文：400/500
- 按钮与小标题：600
- 页面标题：700
- 不再大面积使用 800/900

### 色彩

- 页面背景：`#F5F5F7`
- 内容背景：`#FFFFFF`
- 主文字：`#1D1D1F`
- 辅助文字：`#6E6E73`
- 品牌强调色：深绿色，仅用于主操作、选择和积极状态
- 分隔线：`rgba(60, 60, 67, 0.18)`
- 警告与求助保留明确的橙色和红色语义

### 形状与层级

- 卡片圆角 16px
- 控件圆角 12–14px
- 普通内容不用阴影
- 只有固定底部操作区等真正浮层可以使用轻阴影
- 同一内容区域不出现两层以上的卡片嵌套

## 页面设计

### 首页

- 保留“車なし生活を確認する”为唯一填充式主按钮。
- “今日はどこかに行きたい”改为低一层级的次要操作。
- “家族向けレポート”和“データ確認”放入`家族・支援者の方へ`分组列表。
- 家属与技术入口继续与老人主路径分开。

### 信息设置

- 保留一次一题和固定底部操作。
- 增加语义化进度条，替代只靠文字表达的进度。
- 演示地址提示改为中性信息状态，不再像错误警告。
- 地点选择改为一个分组列表，项目之间使用分隔线，选中项保留勾选和浅色底。

### 诊断结果

- 保留“自然语言结论 → 辅助分数 → 下一步”的顺序。
- 各状态区域改为分组列表。
- 目的地条目减少独立边框。
- “理由を聞く”改为行级紧凑操作，保留可见文字和完整无障碍名称。

### 外出演练

- 任务卡内部的“出发、去程、返程、错过班次”改为单一说明列表。
- 使用分隔线替代四个独立内层卡片。
- “音声で聞く”为主要操作，“家族に共有”为次要操作。

### 日常语音

- 麦克风保持唯一高强调区域。
- 四个目的地按钮改为浅色 tile，移除黑色粗边框。
- 辅助操作放入语义化分组；“困った”继续使用非紧急求助文案和红色语义。

## 组件边界

- `MobileAppShell.tsx`：共享页面背景、标题、返回入口和固定底栏。
- `HomePage.tsx`：首页主次行动和家属工具分组。
- `OnboardingPage.tsx`：进度、地址信息和选择列表。
- `ResultCards.tsx`：诊断分组列表及行级语音操作。
- `RehearsalPage.tsx`：演练说明列表与主次操作。
- `DailyPage.tsx`：语音入口、目的地 tile 和辅助操作分组。
- `styles.css`：统一 token、响应式、交互态和减少动态效果。

## 数据流与错误处理

- 不修改 `AppStateProvider`、API 请求或后端模型。
- 加载、失败重试、演示数据提示和缺失地点提示保持现有行为。
- “困った”继续只显示非紧急帮助信息，不触发紧急呼叫。
- 语音不可用时继续提供按钮路径。

## 测试策略

### 测试驱动行为

1. 首页提供语义化家属工具分组。
2. 信息设置提供可读的进度条。
3. 诊断理由按钮包含目的地名称，避免重复按钮名造成辅助技术歧义。
4. 演练操作区区分主要与次要操作。
5. 日常页辅助操作提供语义化分组。

## 验收标准

1. 首页、信息设置、结果、演练、日常语音页完成统一视觉改造。
2. 每页最多一个填充式高强调主操作。
3. 不出现两层以上卡片嵌套。
4. 所有交互目标不低于 44px，老人主操作 56–64px。
5. 390px 和 430px 视口无横向滚动或底栏遮挡。
6. 选择和状态不只依赖颜色。
7. 前端测试、lint、build 与后端测试通过。
8. 不修改后端、诊断逻辑、地图逻辑或部署配置。

## 范围外

- 家属地图与数据质量后台的完整视觉重设计
- 新路由或底部标签导航
- 暗色模式
- Liquid Glass
- 新图像资产
- 后端或算法修改
- 生产部署

## 风险与护栏

- 降低字重不能降低可读性：正文不小于现有可读范围，避免 Light 字重。
- 减少边框不能降低可操作性：通过背景、分隔线、间距和交互态维持清晰边界。
- 视觉精简不能隐藏演示数据限制或帮助信息。
- 不为视觉一致性修改业务文案事实或错误恢复路径。
